# Mission Mavericks Hub

**Project:** Claim Shield Plus — AI powered motor insurance claims platform
**Tagline:** Own the Mission. Be the Maverick. Win Together.

An enterprise-style internal delivery portal: team directory, project detail, four-week
roadmap, document management and a media gallery, backed by Supabase.

## Technology Stack

- React 19 + TypeScript + TanStack Start (Vite 7)
- Tailwind CSS v4, Motion (animations), Recharts, lucide-react
- Supabase: Postgres, Authentication, Storage, Row Level Security
- ASP.NET Core Web API (external domain services layer in the target architecture)

## Installation

```sh
git clone <repository-url>
cd <repository-name>
npm install
cp .env.example .env   # fill in your Supabase values
npm run dev
```

The app runs at `http://localhost:8080`.

## Environment Variables

See `.env.example`. Browser code reads `import.meta.env.VITE_*`; server code reads
`process.env.*`. Never commit real credentials.

| Variable | Scope |
| --- | --- |
| `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` | Browser |
| `SUPABASE_URL` / `SUPABASE_PUBLISHABLE_KEY` | Server |
| `SUPABASE_SERVICE_ROLE_KEY` | Server only — signed URL generation |

## Architecture

```
React → ASP.NET Core Web API → Supabase Authentication → Supabase Database
      → Supabase Storage → AI Engine → Dashboard
```

## Supabase Setup

1. Create a project and copy the URL and publishable key into `.env`.
2. Apply the SQL migrations in `supabase/migrations/` (in filename order).
3. Confirm RLS is enabled on every table in `public` — the migrations do this and add
   the matching `GRANT` statements.

Tables: `profiles`, `user_roles`, `admin_allowlist`, `members`, `project_details`,
`roadmap_weeks`, `documents`, `gallery_items`, `activity_logs`, `notifications`.

## Storage Bucket Setup

Two private buckets: `documents` and `gallery`.

- Visitors: view, preview and download through short-lived signed URLs generated by a
  server function (`src/lib/documents.functions.ts`).
- Administrators: upload, edit and delete — enforced by `storage.objects` policies that
  call `public.has_role(auth.uid(), 'admin')`.

## Authentication Setup

Email and password authentication via Supabase. Sessions persist in the browser and are
restored on load. Admin-only controls are gated by the `user_roles` table, never by
client-side flags.

## Admin Setup — creating the first administrator

1. The email `admin@missionmavericks.dev` is present in the `admin_allowlist` table.
2. Sign up with that email from the **Admin login** dialog on the Documents page.
3. The `handle_new_user` trigger runs on signup, creates the profile, and — because the
   email is allowlisted — inserts an `admin` row into `user_roles`.
4. Sign in. Upload, edit and delete controls appear across Documents and Gallery.

To add another administrator, insert their email into `admin_allowlist` **before** they
sign up, or insert an `admin` row into `user_roles` for their user id.

## Deployment Guide

1. Set the environment variables from `.env.example` in your hosting provider.
2. Run `npm run build`.
3. Deploy the generated output; the app targets an edge/worker runtime.
4. Apply pending Supabase migrations against the production project before the first
   request.
